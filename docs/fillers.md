# 話し終わりの相槌 (#17)

話し終わりを端末で検知し、キャッシュ済みの短い相槌を再生する。
STT の文字確定・Dot の返答・ブリッジの往復を待たない。
キャッシュ全体の準備が完了するまでは相槌を出さない。

`FILLER_PHRASES` は最大5文の JSON 配列。`kind: "ack"` は話し終わり、
`kind: "wait"` は待機中に使う。文は順番に選び、内容による選択はしない。
既定は「うん、聞いてみるね」「うん、わかったよ」「ちょっと考えるね」
「うん、聞こえたよ」と、待機用の「まだ調べてるよ」。
空文字または `[]` で相槌と待機タイマーを無効にする。
変更後はブリッジを再起動する。

```sh
export FILLER_PHRASES='[{"kind":"ack","text":"うん、聞いてみるね"},{"kind":"wait","text":"まだ調べてるよ"}]'
```

文は1〜100文字。実際に合成した音声は1文52,428サンプル以内、
5文で最大524,280 bytes（約0.5 MiB）とするため、1〜2秒の短い文を指定する。
長すぎる音声・合成失敗・PSRAM不足の場合は相槌を無効にする。

端末は起動後の接続時に `fillers.set` を受け取る。sanoTTS が使える端末では、
ブリッジが文をかなへ変換し、端末がバックグラウンドで sanoTTS 合成して PSRAM に置く。
通常の `VOICE_MODE=bridge` でも相槌は端末の sanoTTS を使う。
PTT・返答が合成に割り込むと、その合成を中止し、空き時間に再開する。
再接続時は設定を送り直してキャッシュを作り直す。

**重みなし端末 (`caps.sanotts=false`) だけ**、接続時にブリッジの有効な
`TTS_ENGINE` で各文を1回合成し、16 kHz / mono / s16le PCM を端末の PSRAM へ送る。
旧 `TTS_ENGINE=sanotts` 設定の fallback は OpenAI。
この経路には対応する API キーまたはローカル TTS サーバーが必要。
接続時の合成失敗は本文・provider error を含まない `fillers_setup_failed` を記録する。
相槌の合成音声はディスクに保存せず、リポジトリ・配布物にも含めない。

PTTを離す、15秒上限、または端末VADで録音を終了すると、マイクのタスク停止を
確認してスピーカーへ切り替え、ローカル相槌を開始する。録音PCMの送信が遅れても
再生を待たせない。再生中はマイクを開始しない。PTTを新たに押すと相槌を止め、
スピーカーの使用終了後に録音を始める。

ブリッジは `mic.end` 受信から8秒・16秒後に `fillers.play {seq}` を送り、最大2回待機相槌を出す。
返答の `say` 受付、Slack の Dot 投稿受付、新しいPTT、切断、終了で残りのタイマーを取り消す。
返答受付では `fillers.cancel` を先に送り、現在の相槌も止める。
端末もturnのseqと最大2回を検査し、古い命令や取り消し後の命令を無視する。
音声が他の処理で使用中なら待機相槌はキューに残さずスキップする。
通知の再生でも相槌を取り消す。

## 検証と実機エビデンス

`npm run check` でタイマー（返答なし・8秒前・途中返答）、設定、接続時のかな/PCM、
認証済みWebSocketとMCPの結線を確認する。
`bash scripts/test-firmware-host.sh` は sanoTTS無効・有効・VAD有効の3構成で、
キャッシュ準備、ローカル再生、録音停止と送信完了の分離、最大2回、取り消し、
非同期停止中のPCM寿命と端末合成の中断・再開を検証する。

実機では、キャッシュの準備後、合成のテスト文でPTT release / VADから最初の音声まで
**300 ms以内**かを測る。シリアルの `[fillers] mic_end t=...` と
`[fillers] start t=... kind=ack|wait` は本文を含まない端末時刻（ms）。
これはマイク停止後と再生予約の時刻であり、物理的なreleaseや実際の音声開始時刻は
動画/音声計測で別に確認する。ネットワーク送信停滞時も同じ確認を行う。
8秒超の返答待ち、途中返答での停止、自分の相槌がSTTへ戻らないこと、空設定、
重みなしfallbackも確認する。動画は部屋・人を写さず、ログは
`scripts/redact.sh` と [privacy.md](privacy.md) に従って伏せ字にする。
実機の遅延・音質・自己音声抑止と動画エビデンスは自動テストだけでは確認できない。
